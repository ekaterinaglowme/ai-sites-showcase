Здесь всё по порядку: **установите два скилла → выберите дизайн → заполните один промпт → прикрепите фотографии и отправьте его**. Установка скиллов — отдельный подготовительный шаг. В промпте для сайта уже только само задание.

## 1. Перед началом установите скиллы

Скиллы — дополнительные инструкции, которые помогают ИИ собирать структуру и дизайн сайта. Для этого урока нужны `landing-page-design` для структуры страницы и `design-taste-frontend` для визуальной работы. Ссылки на оба скилла уже есть в запросе ниже.

### Установите скиллы одним сообщением в Codex

Для установки не нужно открывать GitHub, скачивать архивы или вводить команды в терминале. Ссылки ниже ведут на публичные исходники скиллов; **просто скопируйте запрос целиком и отправьте его в Codex**, который работает с файлами на вашем компьютере. Codex сам найдёт нужные папки и выполнит установку. Если приложение попросит подтвердить действие, проверьте названия двух скиллов и подтвердите.

```text
Используй $skill-installer. Установи для моего пользователя два скилла по ссылкам:
1. landing-page-design: https://github.com/elayadesign/ai-design-skills/tree/main/skills/landing-page-design
2. design-taste-frontend: https://github.com/Leonxlnx/taste-skill/tree/main/skills/taste-skill
Проверь инструкции авторов и установи каждый скилл целиком. Если скилл уже установлен, не устанавливай его повторно. После установки проверь, что оба доступны, и сообщи результат отдельно по каждому. Если что-то не удалось, объясни причину и следующий шаг. Сайт пока не создавай.
```

Дождитесь ответа Codex о двух скиллах. Если после установки один из них не появился, попросите Codex проверить доступность ещё раз; при необходимости откройте новый чат или перезапустите приложение. Это указано и в [официальной инструкции OpenAI о скиллах](https://learn.chatgpt.com/docs/build-skills). Повторять установку для каждого нового сайта не нужно.

**Аккаунт GitHub не нужен.** Ссылки служат адресами исходников для Codex. Вам не нужно заходить на сайт GitHub или скачивать оттуда файлы вручную.

### На чём будет работать сайт?

**В этом уроке мы создаём статический сайт на HTML, CSS и JavaScript, без React.**

- **HTML (`index.html`)** — содержимое: заголовки, тексты, фотографии и разделы страницы.
- **CSS (`style.css`)** — оформление: цвета, шрифты, отступы и расположение блоков на компьютере и телефоне.
- **JavaScript (`script.js`)** — поведение: анимация за курсором, меню и другие интерактивные элементы. Простые раскрывающиеся блоки могут работать и средствами HTML.
- **Папка `images`** — фотографии и иллюстрации вашего сайта.

Браузер открывает HTML, подключает стили, изображения и скрипт — и показывает страницу. **React — отдельная библиотека для интерфейсов; для этой визитки она не требуется.** Не нужно выбирать между «HTML или JavaScript»: здесь они выполняют разные задачи и работают вместе.

Вы не пишете эти файлы вручную. Вы заполняете один промпт, прикладываете фото, а Codex создаёт файлы и запускает предпросмотр. Установка скиллов не добавляет их на сайт: они помогают Codex выполнить работу. Сайт пока находится на вашем компьютере; на втором уроке разберём GitHub и деплой — публикацию по общей ссылке. Форма, которая действительно отправляет заявки, потребовала бы отдельного сервиса; в этом уроке используем ссылки на ваши контакты.

## 2. Подготовьте свои материалы

Создайте на компьютере пустую папку, например `Мой сайт`. В отдельную папку `Материалы` сложите фотографии и логотип. Оригиналы сохраните у себя отдельно. Переименуйте файлы понятно: `portrait.jpg`, `work-01.jpg`, `product-01.png` и так далее.

Для **сайта-визитки** нужны: имя, занятие в одном предложении, 2–4 направления работы, короткий рассказ о себе, основная ссылка для связи и ваше чёткое фото лица. Codex использует его как референс внешности для 3D-аватара первого экрана; для блока «Обо мне» приложите фотографию — можно использовать тот же исходный снимок. Работы или отзывы добавляйте только если они настоящие и их можно публиковать.

Для **сайта школы, студии или проекта** нужны: название, описание, аудитория, направления, контактная ссылка и 3–6 собственных фотографий. Логотип необязателен. Год основания, проекты, города, клиенты и результаты нужны только тогда, когда вы можете их подтвердить. Не переносите фотографии или контакты с сайта-примера на свой сайт.

Укажите один **главный способ связи**: полную ссылку `https://t.me/...`, адрес почты для `mailto:` или номер для `tel:`. Кнопка без настоящего адреса выглядит рабочей, но разочарует посетителя.

## 3. Откройте рабочую папку

Скачайте [настольное приложение ChatGPT](https://learn.chatgpt.com/docs/quickstart) для своей системы, установите и войдите в аккаунт. В новом чате выберите **Codex** и откройте созданную папку `Мой сайт`. В этой папке Codex сможет создавать и менять файлы. Это соответствует [официальному быстрому старту](https://learn.chatgpt.com/docs/quickstart).

Обычный чат ChatGPT может помочь написать текст и объяснить шаги, но для создания и проверки файлов в вашей папке используйте Codex в приложении. Альтернатива без локальной папки — [ChatGPT Work с Sites](https://developers.openai.com/training/walkthroughs/building-a-shareable-site), если Sites доступен вашему аккаунту; порядок публикации там другой.

## 4. Сайт-визитка — один цельный промпт

Ориентир по стилю и композиции — [готовый сайт Екатерины Никольской](https://ekaterinaglowme.github.io/ai-sites-showcase/nikolskaya-romans/). В промпт включены прелоадер с вашим именем и оптимизация фотографий для телефона. Он ненадолго показывает «ЗАГРУЗКА», пока готовится первый экран, и автоматически исчезает.

Выберите свою профессию, тексты, фото и контакты. Замените все квадратные скобки. Пример показывает композицию; имя Екатерины, её проекты и аватар переносить в свой сайт не нужно.

```text
Создай с нуля в открытой папке мой одностраничный сайт-визитку целиком, со всеми разделами из ТЗ. Сам создай файлы, запусти локально и проверь результат. Объясняй действия понятно новичку.

Главный визуальный референс — готовый сайт Екатерины Никольской: https://ekaterinaglowme.github.io/ai-sites-showcase/nikolskaya-romans/
Открой страницу с самого верха, а не только блок #about. Изучи всю композицию на компьютере и телефоне: первый экран, порядок разделов, сетку, относительные размеры, отступы, цвета, типографику, фотографии, контакты и поведение элементов. Повтори визуальную систему максимально близко, заменив личные данные и материалы на мои. Если ссылка недоступна, опирайся на подробное ТЗ ниже. Если я приложу скриншоты, используй их для уточнения композиции. Не утверждай, что изучил сайт, если открыть его не удалось.

ВИЗУАЛЬНОЕ ТЗ — МАКСИМАЛЬНО БЛИЗКО К ПОКАЗАННОМУ ОБРАЗЦУ
1. Общий характер: контрастный типографический сайт, почти чёрный фон #090909, молочно-белый текст #F3F2EE, холодный голубой #91AFFF. Без градиентных карточек, разноцветных плашек и декоративных теней.
2. Шапка: слева короткое имя, по центру компактные ссылки на разделы, справа Telegram или мой контакт в прямоугольной кнопке с тонкой рамкой. Боковые поля около 5% ширины. Левый край имени в шапке совпадает с левым краем основного заголовка, логотипов и описания.
3. Первый экран на компьютере: двухколоночная композиция. Левая часть примерно 55%, правая 45%. Имя и фамилия в две строки, крупный узкий жирный шрифт с кириллицей наподобие Oswald 700. Фамилия курсивом. Заголовок ориентировочно 80–130 px на экране 1440 px, подобрать по длине моего имени. Сохрани разборчивость и силуэт образца, не растягивай буквы искусственно.
4. Справа — 3D-аватар, созданный по точному английскому промпту ниже с использованием моего фото как референса внешности. Размести его крупно на прозрачном фоне, почти на всю доступную высоту первого экрана, без прямоугольной подложки, обрезанных волос и перекрытия имени. Не подменяй 3D-рендер вырезкой из фотографии.
5. Под именем — одна строка логотипов моих инструментов высотой около 32–40 px, равные интервалы 24–32 px. Ниже короткое описание обычным шрифтом 16–18 px. Не добавляй инструменты, которых нет в моём списке.
6. Ниже: крупные заголовки, заметные изображения работ, тонкие разделители и просторные поля. Чередуй чёрный и тёплый светлый #F3F0E8 фон. Контактный блок — светлый, заголовок чёрный, большая ссылка со стрелкой, как в этом ТЗ. Не упаковывай каждый абзац в отдельную карточку.
7. Лёгкий плавный отклик аватара на курсор: заметный, но без скачков; до 20–30 градусов по горизонтали и 10–15 по вертикали. Это декоративный наклон изображения, не настоящий поворот лица. На сенсорных устройствах оставь спокойную статичную композицию.
8. Если приложены скриншоты готового сайта Екатерины, они важнее приблизительных чисел в этом ТЗ: повторяй сетку, относительные размеры, интервалы, расположение элементов и иерархию максимально близко. Меняй только мои тексты, изображения и ссылки. Точное совпадение оценивай по скриншотам одинаковой ширины, а не по памяти.
Хочу чёрный первый экран, крупную выразительную типографику: имя и фамилия слева в две строки, справа мой сгенерированный 3D-аватар. Ниже слева короткое описание и ряд логотипов инструментов, которыми я действительно пользуюсь. Верхняя ссылка с моим именем, заголовок, логотипы и описание должны начинаться на одной вертикальной линии. Остальные секции чередуют светлый и тёмный фон. Не копируй чужие имя, тексты, фото, контакты и кейсы.

СНАЧАЛА СОЗДАЙ 3D-АВАТАР ДЛЯ ПЕРВОГО ЭКРАНА
Используй приложенное моё фото лица как референс внешности и сохрани узнаваемые черты. Передай инструменту генерации следующий английский промпт без перевода, сокращений и дополнений:
Ultra stylized 3D character head render, floating hlead, smooth rounded anatomy, high-gloss porcelain skin, strong specular highlights, soft subsurface scattering, waxy plastic skin shader, minimal micro-detail, slightly exaggerated facial proportions, relaxed expression, glossy lips, clean elegant, face geometry, hair rendered as smooth flowing sculpted strands, shiny polymer-like material, premium CGI quality, modern animation studio style, hyper-polished surfaces, shift cinematic lighting, beauty render, surreal toy-like realism, extremely clean 3D look.

Сохрани получившийся 3D-аватар как PNG с прозрачным фоном отдельно от исходного фото. На сайте используй оптимизированные прозрачные WebP-версии. Исходное фото не ставь на первый экран. Для блока «Обо мне» используй указанную фотографию без изменения лица; если написано «ТО ЖЕ ФОТО», возьми исходный снимок. Если генерация изображений недоступна или фото лица не приложено, скажи об этом прямо и запроси недостающий материал; не подменяй 3D-аватар обычным фото.

Структура в порядке образца: шапка → чёрный первый экран → светлый блок крупных направлений деятельности → светлый блок «Обо мне» → чёрный блок работ → светлый блок услуг → чёрный блок курса/полезных материалов с раскрывающимися пунктами → светлый контактный блок → чёрный футер.
В блоке «Обо мне» слева подпись, крупный заголовок «Привет, я [имя]», два коротких абзаца и кнопка связи. Справа моя фотография строго квадратная: aspect-ratio:1; width:min(100%,500px); object-fit:cover; без растягивания и фильтров. На телефоне максимум 380px и не шире контейнера. Не позволяй высоте изображения растянуть весь раздел. Шапка, имя первого экрана, «Обо мне», абзацы и кнопка начинаются с общей вертикали: 5vw на компьютере и 20px при ширине до 650px. Текст — Manrope, заголовки — Oswald 700 с кириллицей. Не подменяй их похожим широким шрифтом, если исходные доступны.
Контакты сохраняют светлый фон и чёрную типографику как в этом ТЗ, а не произвольный голубой блок. Не придумывай отзывы, клиентов, цифры, квалификацию, результаты и проекты. Если данных для раздела нет, убери его.

На компьютере имя слева, изображение справа без наложения. На телефоне сначала имя, затем аватар, описание и контакт. Центрируй видимую голову относительно экрана с учётом прозрачных полей изображения. Проверь центровку на ширинах 320 и 390 px. Логотипы поставь в одну линию с равными отступами; на узком экране аккуратно адаптируй. Не используй логотипы как доказательство партнёрства.

Можно добавить лёгкий наклон аватара за курсором. Это PNG, а не настоящая 3D-модель: не обещай вращение вокруг головы. Для prefers-reduced-motion отключи движение. Не закрывай кнопки изображением.

Добавь прелоадер: полноэкранный чёрный фон #090909, по центру крупно моё имя и первая буква фамилии (например «МАРК Б.»), шрифт Oswald 700; под именем подпись «ЗАГРУЗКА» и тонкая движущаяся полоса акцентного цвета. Без слоганов и выдуманных процентов. Показывай его только до готовности главного изображения и шрифта, без минимальной искусственной задержки. ```
```

**Пример понятного описания:** «Хочу сайт как спокойный архитектурный журнал: молочный фон, чёрные тонкие заголовки с засечками, большие фотографии и много воздуха. Без цветных карточек и теней. Одна заметная кнопка вверху. На телефоне фото должно идти после заголовка».

Оценивайте не только красоту: имя и занятие должны читаться сразу, основное действие — быть заметным, а текст на телефоне — помещаться без обрезки.

## 7. Следующий урок — публикация

**На втором уроке будем публиковать сайт на GitHub и изучать деплой.**

В первом уроке мы создали сайт и проверили его на компьютере. Сейчас достаточно сохранить готовую папку проекта, фотографии и понравившуюся версию дизайна.

### Что будет дальше

1. Разберёмся, что такое GitHub, репозиторий и коммит.
2. Загрузим файлы сайта в свой репозиторий.
3. Изучим деплой — публикацию сайта из файлов проекта в интернете.
4. Настроим GitHub Pages и получим публичную HTTPS-ссылку.
5. Научимся обновлять сайт и возвращаться к предыдущей версии.

### Что подготовить ко второму уроку

— Готовую папку сайта с `index.html`, стилями и изображениями.
— Проверенную локальную версию, которая вам нравится.
— Аккаунт заранее создавать не нужно: этот шаг пройдём на втором уроке.

Локальная ссылка с `localhost` работает на вашем компьютере. Ссылка для других людей появится после деплоя во втором уроке.

```text
Сохрани текущую согласованную версию сайта. Проверь, что все файлы и изображения находятся в папке проекта. Напиши, где она лежит и как снова открыть локальный сайт. Публиковать пока не нужно — это сделаем на втором уроке.
```

## 8. Если что-то пошло не так

| Что случилось | Что попросить у Codex |
|---|---|
| На локальном сайте нет оформления | `Проверь, что CSS подключён и все пути к изображениям ведут к существующим файлам.` |
| Видна старая версия | `Проверь локальный сервер и кеш браузера. Обнови страницу и покажи текущую версию сайта.` |
| С телефона заголовок обрезан | `Проверь ширину 390 px, перенеси заголовок и уменьшай размер только там, где это нужно.` |
| Кнопка ведёт не туда | `Составь таблицу всех href и исправь кнопку [НАЗВАНИЕ] на [ТОЧНЫЙ URL].` |
| ИИ придумал проект или отзыв | `Удали неподтверждённый факт и проверь весь сайт на другие вымышленные утверждения.` |
| Фото чужой компании показано как ваше | `Замени фото на мой файл [ИМЯ ФАЙЛА] или убери блок. Не называй иллюстрацию нашей работой.` |

**Критерий готовности:** ваш сайт показывает именно ваши материалы, открывается локально, читается на мобильной ширине, а все кнопки ведут туда, куда вы ожидаете.
